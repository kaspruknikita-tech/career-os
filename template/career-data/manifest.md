# MANIFEST — индекс блоков опыта

Читается вместо всех блоков сразу. Скилл смотрит сюда, выбирает 8-14 релевантных блоков и читает только их. В этом вся экономия: библиотека растёт, стоимость запроса — нет.

Строка добавляется при каждом новом блоке. Пишет только `career-data-keeper`.

## Правила отбора

1. Блок = один кейс одной компании. Не «всё про аналитику», а конкретное сделанное дело.
2. ID блока = префикс компании + тема: `<pre>-<тема>`. Префиксы ниже.
3. Обязательные компании — те, что идут в каждое резюме. Отмечены в таблице компаний.
4. Блок ниже 60% релевантности вакансии не читается.

## Компании

| Префикс | Компания | Период | Обязательная |
|---|---|---|---|
| <pre> | <название или «NDA, отрасль»> | <MM/YYYY - MM/YYYY> | да / нет |

Период здесь — источник истины. Даты внутри блоков не должны за него выходить.

## Блоки

| ID | Тема | Архетипы | Метрика | Статус |
|---|---|---|---|---|
| <pre>-<тема> | <о чём кейс> | <ID архетипов через запятую> | <цифра или «качественный»> | draft / ready |

`draft` — черновик, в резюме не идёт. `ready` — проверен, можно брать.

## Как читать этот файл скиллу

1. Определить архетип вакансии.
2. Отфильтровать блоки по колонке «Архетипы».
3. Для каждой роли резюме решить число буллетов отдельно.
4. Прочитать только отобранные файлы из `blocks/`.

Не читать весь каталог `blocks/`. Не читать блоки, не попавшие в отбор.
