# Discovery — закрытие пробела через вопросы

Когда:
- ATS Match Score вакансии < 90% (оценка или адаптация) — по каждому значимому пункту из Missing Keywords / GAP спросить, есть ли опыт. Вопросы можно задать одним сообщением списком, не обязательно по одному за раз.
- Вне зависимости от общего score: вакансия требует то, чему нет блока выше 60% (полоса WEAK/GAP из `matching-strategies.md`) и требование критично для этой вакансии.

Не превращать в допрос по каждой мелкой формулировке — фокус на пунктах, которые реально двигают score или закрывают критичное требование.

## Вопрос

Технический пробел: "Был опыт с {X}?"
Софт-скилл пробел: "Был случай, когда пришлось {Y}?"

## Ветвление по ответу

- **Да, уверенно** → углубиться: масштаб, метрика, было ли это в проде или разово.
- **Косвенно** ("не совсем то, но...") → спросить про перенос на нужный навык.
- **Смежное** → оценить дистанцию до требования вакансии.
- **Нет** → не настаивать, зафиксировать как честный пробел.

## Фиксация результата

Если нашлось что-то реальное — это новый блок или дополнение к существующему, не разовая правка резюме:

```
Компания/контекст: ...
Что сделал: ...
Результат/метрика: ...
Закрывает требование: ...
```

Показать пользователю черновик в формате блока (см. `career-data/blocks/*.md` для образца), спросить: добавить в `core.md` (метрика) + создать блок в `blocks/`? Никогда не сохранять молча — блоки правит только пользователь через явное подтверждение.

## Правило

Помогать сформулировать то, что реально было — не придумывать. Если после вопроса ничего не нашлось, это остаётся честным пробелом: см. `core.md` → "Честные пробелы" и шаблон закрытия в `matching-strategies.md`.
