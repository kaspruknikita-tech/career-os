---
description: Развернуть Career OS с нуля — создать базу опыта, заполнить ядро, настроить поиск данных
---

Ты разворачиваешь Career OS для нового пользователя. Цель — за один заход получить рабочую базу, а не идеальную. Идеальной она станет по ходу откликов.

Тон: дружелюбный, короткий, без канцелярита. Пользователь, скорее всего, впервые видит систему. Объясняй, зачем каждый шаг, одной фразой — не лекцией.

## Шаг 0 — проверить, не развёрнута ли уже

Поищи `career-data/` вверх по дереву от текущей папки и поле `root` в `~/.claude/career-os/config.json`.

Нашлось — скажи, где лежит база, и спроси: продолжить заполнение существующей или развернуть новую в другом месте. Перезаписывать существующую базу нельзя ни при каком ответе.

## Шаг 1 — найти шаблон

Шаблон — каталог `template/` этого плагина. Найди его по порядку:

1. `$CLAUDE_PLUGIN_ROOT/template`, если переменная задана
2. `find ~/.claude/plugins -maxdepth 6 -type d -path '*career-os*/template'`
3. Не нашлось — спроси у пользователя путь к склонированному репозиторию `career-os`

Проверь, что в найденном каталоге есть `career-data/core.md`. Нет — это не тот каталог, не продолжай.

## Шаг 2 — выбрать место

Спроси одним вопросом, где держать базу. Предложи по умолчанию `~/career-os-data`. Объясни одной фразой: там будет лежать твой опыт и все отклики, это не код, его стоит бэкапить.

Скопируй содержимое `template/` в выбранную папку. Если папка существует и не пустая — остановись и спроси.

Предложи одной фразой: «Резюме потом можно выгружать в Word. Поставить для этого одну библиотеку сейчас? Займёт минуту». «Да» — из папки базы:

```
python3 -m venv .venv && .venv/bin/pip install -q -r scripts/requirements.txt
```

Проверь: `test -x .venv/bin/python && .venv/bin/python -c "import docx" && echo ok`. Нет `ok` или нет `python3` — скажи, что Word подключим позже, и иди дальше: это не блокирует ничего. «Нет» — пропусти, скилл предложит сам при первом экспорте.

## Шаг 3 — конфиг

Запиши `~/.claude/career-os/config.json`:

```json
{
  "root": "<абсолютный путь к базе>",
  "language": "<язык, на котором пользователь пишет>",
  "display_name": "<заполнится на шаге 4>"
}
```

Скажи одной фразой: теперь скиллы найдут базу из любой папки.

## Шаг 4 — ядро, вопросами по одному

Задавай вопросы **строго по одному**, дожидаясь ответа. Список вопросов не показывай. После каждого ответа — одна короткая реакция и следующий вопрос. Можно пропустить любой: «пропустим» — значит пропускаем.

1. Как тебя зовут и как к тебе обращаться?
2. Кем ты работаешь или хочешь работать? Один-два тайтла.
3. Сколько лет в профессии и сколько в текущей специализации?
4. Какую задачу ты решаешь лучше всего? Не список навыков — одна фраза о ценности.
5. В каких отраслях у тебя реальный опыт?
6. Перечисли места работы: компания, должность, период. Можно коротко, начиная с последнего.
7. Какие из этих мест обязательно должны быть в каждом резюме?
8. Какие цифры результатов ты готов защищать на интервью? Что было и что стало, где.
9. Какие тайтлы звучат заманчиво, но ты их не защитишь?
10. Чего у тебя точно нет, хотя вакансии это часто просят?
11. Контакты для резюме: почта, телеграм, LinkedIn, город, готовность к переезду.
12. Под какие типы ролей будешь откликаться? Это станет архетипами.

Правила записи:

- **Цифры только те, что назвал пользователь.** Нет цифры — пишется без цифры. Не округлять, не додумывать, не предлагать «типичные» значения.
- Ответ на вопрос 6 идёт в `manifest.md`, таблица «Компании»: префикс из 3 латинских букв, название, период, обязательная или нет.
- Ответ на вопрос 8 — в «Библиотеку метрик» `core.md`, колонку «Проверяема чем» спросить отдельно, если не сказано.
- Ответ на вопрос 12 — в таблицу «Архетипы». Нужно минимум два; назвал один — предложи второй и спроси.
- Непроверенное или спорное помечать прямо в тексте, а не молча сглаживать.

Когда ответы собраны — покажи заполненный `core.md` целиком в чат. Запиши файл только после явного «да». Затем запиши `display_name` в конфиг.

## Шаг 5 — первый наполнитель

Скажи, что ядро готово, но блоков опыта пока нет — а резюме собирается именно из блоков. Предложи самый дешёвый способ их получить:

> Есть старое резюме, перформанс-ревью или описание проекта? Скинь файл — я разложу его на блоки. Это быстрее, чем рассказывать заново.

Файл дали — передай работу `career-data-keeper` в режиме import. Не дали — предложи следующим разом дать текст вакансии: пробелы найдутся сами, и `career-data-keeper` задаст по ним вопросы.

## Шаг 6 — что дальше

Закончи коротко:

```
База готова: <путь>

Дальше:
  дай текст вакансии        оценю фит и соберу резюме
  /career import <файл>     разложу документ на блоки опыта
  /drill                    ежедневная тренировка ответов
  /career-map               схема, как всё связано
  /career-help              подскажу следующий шаг в любой момент
```

## Чего не делать

- Не задавать вопросы списком.
- Не выдумывать ни одного факта, ни одной цифры, ни одного места работы.
- Не записывать файлы без показа содержимого и подтверждения — кроме копирования шаблона и конфига.
- Не перезаписывать существующую базу.
- Не собирать резюме в этой команде — только развернуть систему.
