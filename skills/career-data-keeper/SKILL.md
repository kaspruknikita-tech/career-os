# career-data-keeper

Хранитель базы опыта `career-data/`. Единственный скилл, который в неё пишет.

База уже собрана: 34+ блока, manifest с архетипами, core.md. Задача keeper — держать её живой: добавлять новый опыт, закрывать пробелы, обновлять ядро при смене работы.

## Пути

Корень базы: `career-data/`

| Файл | Роль |
|---|---|
| `core.md` | Ядро: идентичность, контакты, архетипы. Правки инвалидируют prompt cache — трогать только в режиме update |
| `manifest.md` | Индекс блоков. Каждый новый блок = новая строка |
| `blocks/*.md` | Блоки опыта |
| `gaps.md` | Пробелы: что рынок спрашивает, а в базе нет |

## Границы

Пишет только внутри `career-data/`. Не трогает `drill/`, `output/`, `reference/`.

Ничего не записывает без явного подтверждения пользователя. Черновик показывается в чат целиком, потом вопрос «пишу?».

## Первое действие любого режима

Прочитать `gaps.md` (первые 15 строк — таблица отсортирована по числу встреч вниз). Есть строки со счётчиком >=3 и статусом не `closed` — вывести маяк ДО всего остального:

```
ГОРЯЧИЕ ПРОБЕЛЫ (>=3 встреч)
  ITIL Change Management  4 встречи  no-exp    -> кандидат в спринт drill
  SQL оконные функции     3 встречи  unformed  -> опыт есть, оформить блоком
```

Маяк выводится один раз за сессию, не повторяется.

## Режимы

| Команда | Что делает |
|---|---|
| `/career import <файл>` | Документ → черновики блоков |
| `/career gap [тема]` | Интервью по пробелу → блок. Без темы — берёт самый горячий `unformed` из gaps.md |
| `/career update` | Смена работы, повышение, новая компания → правка core.md и manifest |
| `/career gaps` | Показать таблицу пробелов целиком, без действий |

### import

1. Прочитать документ. `.docx` — через `python-docx` из venv: `python3`. `.pdf` — попробовать текстовый слой, скан не разбирать, сказать честно.
2. Прочитать `manifest.md`. Для каждого найденного куска опыта проверить: есть ли уже блок про это.
3. **Дубль — не создавать новый блок.** Показать существующий блок и спросить: дополнить его или это отдельный кейс. По умолчанию дополнить.
4. Собрать черновики по `references/block-contract.md`. Правила извлечения — `references/document-extraction.md`.
5. Метрики из документа помечать как непроверенные, пока пользователь не подтвердит. Документ это заявка, не подтверждение.
6. Показать черновики, дождаться «да», записать блоки + строки в manifest.

### gap

1. Тема не названа — открыть `gaps.md`, предложить самый горячий `unformed`, затем самый горячий `open`.
2. Провести интервью по `references/gap-interview.md`. Вопросы по одному. Дожимать до метрики.
3. Опыта нет — не выдумывать. Проставить в gaps.md статус `no-exp` и записать в колонку «Что ответил» его формулировку своими словами. Это не провал, это экономия времени на будущее.
4. Опыт есть — собрать блок по контракту, показать, записать после подтверждения.
5. После записи блока: строка в gaps.md → статус `closed`, в колонку ответа `-> block-id`.

### update

1. Спросить, что изменилось: новая компания, новая должность, новый проект на текущей.
2. Правки `core.md`: идентичность, стаж, позиционирование, домены. Стаж пересчитать от дат в `manifest.md`, а не прибавить год к старой цифре.
3. Новая компания — новая секция в `manifest.md` с датами, по образцу существующих.
4. Показать diff словами до записи. core.md — самый дорогой файл в базе, правки инвалидируют кэш.

## Жёсткие правила

1. Не изобретать опыт. Фактура только от пользователя или из документа.
2. Не изобретать метрики. Нет цифры — писать «Без числовой метрики». Выдуманная цифра палится на интервью первой.
3. Не писать в `blocks/`, `manifest.md`, `core.md` до явного «да».
4. Сначала сверка с manifest, потом создание. Дубль хуже отсутствия блока: resume-tailor возьмёт оба и в резюме будет два буллета об одном.
5. Есть непроверенная или спорная часть — обязательна секция «Осторожно» в блоке. Она защищает на интервью.
6. Без em dash, без эмодзи. Язык — поле `language` в `~/.claude/career-os/config.json`, нет поля — язык пользователя.
7. **Числовая метрика сверяется по величине, а не по совпадению строки.** Перед тем как назвать метрику пробелом, проверить `core.md` на агрегат того же вида (максимум по портфелю, диапазон, суммарный объём), который её покрывает, и `gaps.md` на тему с любым статусом. Область поиска — `core.md` и `gaps.md`, не только `blocks/`. Автоматическая сверка находит расхождение строк, а не расхождение фактов, поэтому её вывод проходит ручную проверку до того, как будет предъявлен как находка.
8. **Строка в `gaps.md` вставляется от заголовка своей секции.** Найти `## Пробелы`, найти следующий заголовок того же уровня (`## Статусы`), вставлять внутри промежутка. Не привязываться к последнему совпадению `^|` по файлу: таблиц несколько, последняя — «Кто пишет», и строка молча уедет туда. После записи вывести номер строки и соседей сверху и снизу.

## Красные флаги — остановиться

- Собираешься записать блок, не показав черновик
- Формулируешь метрику, которую пользователь не называл
- Создаёшь блок, не открыв manifest
- Пишешь «внедрил X», когда в ответе было «участвовал в X»
- Правишь core.md вне режима update
- Пишешь в `drill/` или `output/`

Любой из них означает: остановиться, показать, спросить.

## Кто ещё читает эту базу

`resume-tailor`, `cover-letter`, `interview-prep` и `daily-drill` — только читают. Формат блока держать стабильным: сломанный контракт ломает всех читателей. `channel-finder` базу не читает вовсе.
