# Как проверить Career OS

Час времени, старое резюме и одна живая вакансия. Больше ничего не нужно.

Лучше всего проверять на своих настоящих данных: система работает от фактов, и на выдуманных видно меньше. Всё остаётся у тебя на диске.

## Перед началом

Если у тебя уже стоят скиллы с именами `resume-tailor`, `cover-letter`, `interview-prep`, `channel-finder`, `career-data-keeper` или `daily-drill` — они будут конфликтовать с плагином. Временно переименуй их папки в `~/.claude/skills/`.

## Что проверить

Каждый пункт: что сделать → что должно произойти. Не произошло — это и есть находка.

### Установка

- [ ] Поставь плагин по README → в списке команд появились `/career-init`, `/career-help`, `/career-map`, `/career-feedback`
- [ ] `/career-help` в пустой папке → предлагает `/career-init` и больше ничего не рассказывает
- [ ] `/career-map` → показывает схему, кто что читает и пишет

### Первый запуск

- [ ] `/career-init` → вопросы приходят по одному, любой можно пропустить
- [ ] Не называй цифры результатов или назови размыто → в `core.md` нет ни одной цифры, которую ты не говорил
- [ ] Перед записью `core.md` показан тебе целиком и ждёт «да»
- [ ] В выбранной папке появились `career-data/`, `drill/`, `reference/`, `scripts/`

### Работа

- [ ] `/career import <старое резюме>` → черновики блоков опыта, запись только после подтверждения
- [ ] Дай текст вакансии и попроси оценить фит → ATS-оценка числом в процентах, список недостающих требований
- [ ] Попроси собрать резюме → резюме сначала в чате; в разделе навыков короткие теги, а не куски предложений; ни одной цифры не из твоей базы
- [ ] Попроси выгрузить резюме в Word → если библиотеки нет, предлагает поставить её одной командой; после «да» появляется `.docx`, который открывается в Word
- [ ] «Напиши сопроводительное» → 120–180 слов, нигде нет «опыта с X нет»
- [ ] «Куда откликаться в <компания>» → у каждого контакта ссылка на источник или пометка «выведен»
- [ ] `/drill` → даёт кейс и ждёт ответа, не подсказывает; разбор по тактам T1–T4 и отдельно closing

### Из другой папки

- [ ] Открой Claude Code в любой другой папке, спроси «что там по пробелам» → база находится сама

## Что записывать по ходу

Не надо вести отчёт. Достаточно замечать четыре вещи:

- где **смутило** — не понял, что происходит или что делать дальше
- где Claude **выдумал** факт или цифру
- где **застрял** — ошибка, ничего не произошло, ушло не туда
- что **понравилось**

## Как отправить отзыв

В конце, в той же сессии:

```
/career-feedback
```

Команда сама соберёт, что происходило, задаст три коротких вопроса, вычистит всё личное, покажет черновик и после твоего «да» создаст issue. Одно нажатие.

Без Claude — [открой форму](https://github.com/kaspruknikita-tech/career-os/issues/new?template=feedback.yml) напрямую.

## Для тех, кто хочет глубже

Поставь [task-observer](https://github.com/rebelytics/one-skill-to-rule-them-all) перед проверкой. Он сам ведёт журнал: где скилл нарушил своё правило, где ты поправил методологию, где всплыл дефект. `/career-feedback` в конце предложит приложить его выводы — только заголовки и принципы, без контекста.

Это тяжелее обычного пути: у скилла свой протокол и журнал на диске. Выбирай его, если готов потратить больше времени ради более точного отзыва.
