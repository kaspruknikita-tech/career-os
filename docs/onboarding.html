Установка

Нужен Claude Code. Одна из двух веток.

Плагином проще

Команды и скиллы ставятся разом и обновляются вместе.

/plugin marketplace add kaspruknikita-tech/career-os
/plugin install career-os

Вручную

Если плагины не нужны. Мастер первого запуска потом спросит путь к этой папке.

git clone https://github.com/kaspruknikita-tech/career-os.git
cp -R career-os/skills/* ~/.claude/skills/
cp career-os/commands/* ~/.claude/commands/

Уже стоят свои скиллы с именами resume-tailor, cover-letter и подобными — временно переименуй их папки, иначе будут конфликтовать.

Первые двадцать минут

Три шага. Порядок важен: без ядра нечего раскладывать, без блоков не из чего собирать резюме.

  1. Развернуть базу

    /career-init

    Двенадцать вопросов по одному: кем работаешь, где, какие цифры готов защищать на интервью, чего точно нет. Любой можно пропустить. Перед записью покажет готовое ядро целиком и дождётся «да».

    около 15 минут

  2. Загрузить старое резюме

    /career import ~/Downloads/резюме.pdf

    Разложит документ на блоки опыта: один блок — один кейс одной компании. Метрики из документа пометит как непроверенные, пока ты их не подтвердишь. Самый быстрый способ наполнить базу.

    около 5 минут

  3. Дать первую вакансию

    вот вакансия: [текст], оцени фит

    Классифицирует роль, посчитает совпадение, назовёт недостающие требования и спросит про них одним сообщением. Попросишь резюме — сначала покажет его в чате, файлы запишет после твоих правок.

Не понимаешь, что дальше, в любой момент — /career-help. Он посмотрит, что уже заполнено, и назовёт один следующий шаг.

Кто что читает и кто пишет

Главное правило системы: писать в базу опыта может только один скилл. Остальные читают. Иначе через месяц в базе окажется три версии одного кейса.

Порядок на одну вакансию

  1. resume-tailorОценить фит, собрать резюме. Записать changelog: какие формулировки выбраны.
  2. cover-letterПисьмо на ту же вакансию. Берёт те же формулировки из changelog.
  3. channel-finderКуда отправлять: страница команды, рекрутеры, почты, каналы.
  4. interview-prepЕсли позвали. Вопросы с рынка и та же версия фактов, что в резюме.

Начнёшь с письма — согласовывать его будет не с чем.

Где лежат твои данные

В обычной папке у тебя на диске. Мастер спросит, где её создать. Скиллы находят её сами: сначала ищут вверх от текущей папки, потом в конфиге.

~/career-os-data/
├── career-data/   # опыт: ядро, индекс, блоки, пробелы
├── drill/         # тренировки и ошибки
├── reference/     # форматы и стратегии
├── scripts/       # экспорт в docx
└── output/        # отклики, по папке на вакансию

Это не код, а твой опыт. Его стоит бэкапить.

Что система не делает

  • Не придумывает цифры. Нет в библиотеке метрик — пишет без цифры.
  • Не пишет «опыта с X нет» в резюме и письмах. На интервью — признаёт прямо, со смежным примером.
  • Не меняет блоки опыта под вакансию. Адаптация уходит в output/, оригинал цел.
  • Не записывает контакт без ссылки на источник. Выведенную по шаблону почту так и помечает.
  • Ничего не отправляет сама. Готовит — отправляешь ты.

Отзыв — одной командой

В конце, в той же сессии:

/career-feedback

Сама вспомнит, что происходило в разговоре, задаст три коротких вопроса и уберёт всё личное: компании, контакты, цифры, тексты вакансий. Покажет черновик и после твоего «да» создаст issue на GitHub.

Без Claude — форма на четыре поля.

Если хочешь глубже

Поставь task-observer до начала проверки. Он сам ведёт журнал: где скилл нарушил своё правило, где ты поправил методологию, где всплыл дефект.

/career-feedback предложит приложить его выводы — только заголовки и принципы, без контекста.

Это дольше обычного пути, зато отзыв точнее.
