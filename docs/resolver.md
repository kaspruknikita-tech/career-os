# Где скиллы берут данные

Одно правило на все шесть скиллов. Ни один скилл не содержит абсолютных путей.

## Порядок поиска

1. **Вверх по дереву от текущей папки.** Ищем каталог, внутри которого лежит `career-data/`. Проверяем текущую папку, потом родительскую, и так до домашнего каталога. Нашли — это корень системы, поиск закончен.
2. **Конфиг.** Не нашли — читаем `~/.claude/career-os/config.json`, поле `root`. Путь существует и содержит `career-data/` — это корень.
3. **Ничего нет.** Не говорить «файл не найден». Сказать, что система ещё не развёрнута, и предложить `/career-init`.

Правило намеренно даёт работать без конфига вообще: положил `career-data/` в проект, запустил Claude Code из этой папки — всё работает. Конфиг нужен тем, кто хочет вызывать скиллы из любой директории.

## Что внутри корня

```
<root>/
├── career-data/     база опыта, пишет только career-data-keeper
├── drill/           состояние тренажёра, пишет только daily-drill
├── reference/       методология: форматы, стратегии, источники
└── output/          результаты откликов, создаётся сам
```

Все пути в скиллах пишутся от корня: `career-data/core.md`, `drill/queue.md`, `output/{company}-{role}/`. Никогда `/Users/...`.

## Конфиг

`~/.claude/career-os/config.json`. Скилл его читает, но никогда не создаёт молча — только через `/career-init` или с явного согласия.

```json
{
  "root": "/абсолютный/путь/к/корню",
  "language": "ru",
  "display_name": "Имя Фамилия",
  "drill": {
    "session_minutes": 60
  }
}
```

| Поле | Зачем |
|---|---|
| `root` | Корень системы для вызова из любой папки |
| `language` | Язык ответов скиллов. Нет поля — язык пользователя |
| `display_name` | Как обращаться. Нет поля — «ты» без имени |
| `drill.session_minutes` | Бюджет тренировки |

Состояние тренажёра — позиция в цикле, пауза спринтов и условие её снятия — в конфиг не пишется. Оно живёт в `drill/curriculum-state.md`: одно состояние, один файл.

## Precedence

**Конфиг решает про настройки, скилл решает про процесс.** Конфиг не может ослабить правило: нет поля, которое отключает проверку перед выдачей или разрешает выдумывать метрики. Появилось желание такое поле завести — это признак, что правило не на месте, а не что конфиг неполный.

## Первый запуск

Скилл, не нашедший корень, не падает и не ищет наугад. Он говорит одной фразой, что базы нет, и предлагает `/career-init`. Мастер задаёт вопросы, разворачивает `template/` в выбранную папку и пишет конфиг.

## Почему не переменная окружения

`CAREER_OS_ROOT` работала бы, но требует правки шелл-профиля до первого запуска — то есть ровно в тот момент, когда пользователь ещё не понимает, что ставит. Поиск вверх по дереву не требует настройки вообще, а конфиг пишется мастером, а не руками.
